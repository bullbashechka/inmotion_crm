# 024. Нефункциональная проверка, CI/CD и выпуск

**Этап:** 7. Эксплуатационная готовность

## Цель

Доказать готовность первой версии и настроить независимый безопасный выпуск frontend и API.

## Контекст продукта

Production допускается только после функциональной, нагрузочной, эксплуатационной и юридической проверки контура данных.

## Объём

- Настроить unit/component/integration/Playwright тесты и наборы на целевых объёмах.
- Настроить Cloudflare Pages/Workers Builds, preview и production pipelines.
- Проверить независимые deploy/rollback, совместимость контрактов и expand/contract миграции.
- Провести backup/restore drill и оформить release checklist критериев раздела 35 PRD.

## Вне объёма

Разрушительный автоматический rollback БД и миграции production из preview.

## Требования

- Production идёт из основной ветки после install, typecheck, tests и build.
- Preview не получает production-секреты/данные и не запускает production-миграции.
- Production и demo полностью изолированы.
- Рабочая БД/backups/logs размещаются в разрешённой юрисдикции; Cloudflare-контур письменно согласован до запуска.

## Критерии приёмки

- Все 31 критерия готовности PRD подтверждены тестом или подписанным эксплуатационным доказательством.
- 95% открытий/сохранений ≤2 секунд при 50 000 пациентах, 500 000 записей и 20 сотрудниках; поиск/отчёт/экспорт укладываются в свои лимиты.
- Критические Playwright-сценарии покрывают согласия, права, optimistic locking, расписание, финансы, закрытие случая и demo reset.
- Frontend и API развёртываются и откатываются независимо без нарушения контракта; откат приложения не откатывает миграцию разрушительно.
- Восстановление production-backup успешно проверено в тестовом контуре.
- Есть письменное подтверждение размещения/обработки персональных и медицинских данных до включения production.
