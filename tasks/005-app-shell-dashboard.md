# 005. Каркас интерфейса, настройки клиники и дашборд

**Этап:** 2. Доступ и каркас приложения

## Цель

Создать единый рабочий интерфейс и ролевую сводку текущего состояния клиники.

## Контекст продукта

Интерфейс русскоязычный, desktop-first, с единым часовым поясом клиники и быстрыми действиями.

## Объём

- Реализовать навигацию, защищённые маршруты и состояния loading/empty/forbidden/error.
- Реализовать настройку часового пояса и единые форматы `ДД.ММ.ГГГГ`, 24 часа.
- Реализовать дашборд показателей и быстрых действий из раздела 6 PRD.
- Скрывать и фильтровать виджеты по разрешениям.

## Вне объёма

Полноценный смартфонный интерфейс и неописанный PRD визуальный дизайн.

## Требования

- Минимальная рабочая ширина — 1366×768; Chrome/Edge — две последние стабильные версии.
- Браузерный часовой пояс не меняет расчёт дат клиники.
- Каждый быстрый переход ведёт в доступный сотруднику предметный сценарий.

## Критерии приёмки

- Два пользователя с разными правами видят разные допустимые наборы показателей без утечки значений.
- Смена тестового часового пояса браузера не меняет время клиники на дашборде.
- Ошибка любого виджета не ломает остальные; повтор загрузки безопасен.
- Быстрые действия открывают создание обращения, пациента, записи либо соответствующие разделы согласно правам.

## Зависимости

001–004; наполнение показателей подключается по мере готовности доменов.
