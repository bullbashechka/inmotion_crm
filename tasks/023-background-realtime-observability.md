# 023. Фоновые процессы, живые обновления и наблюдаемость

**Этап:** 7. Эксплуатационная готовность

## Цель

Надёжно выполнять периодические/тяжёлые операции, доставлять живые события и диагностировать сбои без утечки данных.

## Контекст продукта

PostgreSQL остаётся источником истины; Cloudflare-компоненты координируют работу и содержат минимум данных.

## Объём

- Подключить Queues для уведомлений/пересчётов, Workflows для сброса/экспортов и Cron для периодических операций.
- Подключить Durable Objects для доставки событий очереди с fallback на polling.
- Реализовать correlation ID, структурированные безопасные логи, метрики и оповещения.

## Вне объёма

Хранение доменных данных в Durable Objects, прямой Supabase Realtime в браузере.

## Требования

- Сообщения и workflow-state содержат только технические ID и минимум метаданных.
- После события клиент повторно загружает разрешённое состояние через API.
- Логи исключают диагнозы, записи, тесты, реквизиты, пароли, токены и документы.
- Сбои покрываются повторными попытками без частичного результата.

## Критерии приёмки

- Отключение live-канала автоматически включает polling и не блокирует работу очереди.
- Повтор доставки сообщения не создаёт дублей; dead-letter/ошибка видима оператору.
- Cron корректно обрабатывает idle-сессии, просроченные задачи и retention аудита.
- Корреляция связывает API и фоновую ошибку без чувствительных данных в URL, trace headers или тексте.
- Метрики/алерты покрывают ошибки API, latency, PostgreSQL, фоновые задачи и deploy.
