# PostgreSQL: технический фундамент

Предметные таблицы находятся только в `crm`; закрытый журнал — в `crm_internal.schema_migrations`. `crm_runtime` не имеет `USAGE` и прав на `crm_internal`. Bootstrap конвергентно задаёт роли без superuser/создания ролей/БД/репликации/BYPASSRLS и с UTC: `crm_owner` — NOLOGIN; `crm_migrations` — LOGIN и единственный член `crm_owner`; `crm_runtime` не имеет членств. Bootstrap снимает прежние прямые database/public-schema grants и лишние memberships всех трёх ролей.

`backend/drizzle/0000_*.sql` и snapshot создаются Drizzle Kit. `0001_security.sql` зарегистрирован как Drizzle custom migration и содержит controlled SQL для default-deny, точных runtime grants и проверки IANA timezone. Раннер читает тот же каталог, нормализует SQL в LF, сверяет checksum, не допускает отсутствующие/переименованные applied migration и сохраняет advisory lock. Маркер `-- inmotion:no-transaction` предназначен для будущих `CREATE INDEX CONCURRENTLY`: перед SQL создаётся состояние `running`; повторный запуск требует ручной сверки и не выполняет слепой replay.

Для Supabase Data API нельзя публиковать `crm` и `crm_internal`. Preview и production используют разные cache-disabled Hyperdrive IDs. Placeholder в `wrangler.jsonc` не является ресурсом: создайте binding через `wrangler hyperdrive create ... --caching-disabled`. Вне default check запускайте `CLOUDFLARE_ACCOUNT_ID=... CLOUDFLARE_API_TOKEN=... SUPABASE_PROJECT_REF=... SUPABASE_ACCESS_TOKEN=... bun run --cwd backend hyperdrive:preflight`. Скрипт читает ID только из `HYPERDRIVE_FRESH` выбранной Wrangler-конфигурации: по умолчанию `wrangler.jsonc`; для отдельного deployment-конфига задаётся `WRANGLER_CONFIG_PATH`, для named environment — `WRANGLER_ENV` (или стандартный `CLOUDFLARE_ENV`). Placeholder и несовпадающие environment отклоняются. Скрипт fail-closed читает Cloudflare REST `.../hyperdrive/configs/{id}`, требует `result.caching.disabled === true` и сверяет origin с `SUPABASE_PROJECT_REF`, затем читает авторитетный Supabase Management API `GET /v1/projects/{ref}/postgrest` и проверяет `db_schema`; секреты и параметры origin не печатаются.

Worker динамически загружает request-scoped adapter; health route не открывает PostgreSQL. Единственная прикладная граница — `withRequestDatabase`, закрывающая pg client через `try/finally`.

`test:db` и `test:db:performance` требуют `TEST_DATABASE_URL`, `TEST_DATABASE_DISPOSABLE_CLUSTER=1` и COMMENT на admin database: `COMMENT ON DATABASE <имя> IS 'inmotion-task002-disposable';`. Это явное подтверждение, что весь кластер disposable: harness временно меняет cluster-global роли и создаёт/удаляет БД, затем удаляет test roles. Не использовать для shared, preview или production кластеров.
