# План реализации задачи 001

## Выполненные этапы

1. Создать Bun workspace: `webapp`, `backend`, `packages/contracts`; закрепить версии в `bun.lock`.
2. Описать общие Zod-контракты: окружения, статус совместимости, ответ health-check и безопасная ошибка.
3. Поднять Hono API в Cloudflare Worker: `/api/v1/system/health`, OpenAPI, `correlationId`, allow-list CORS с credentials.
4. Создать Vite SPA с Tailwind и базовыми shadcn-совместимыми компонентами; вызывать API только через клиентский адаптер.
5. Зафиксировать UX-решения: заметная постоянная маркировка demo/preview, отсутствие offline-сохранения, сохранение открытой старой вкладки до окончания сессии, остановка при критичной несовместимости окружений.
6. Добавить unit-, contract-, DOM- и Worker-runtime тесты; добавить проверку архитектурных границ.
7. Выполнить полный `bun run check`, затем отметить задачу в `TASKS.md`.

## Инварианты

- Browser не получает серверные секреты и не обращается к БД напрямую.
- CORS отражает только точный настроенный origin и только с credentials.
- Ошибки API не содержат внутренние детали; `correlationId` связывает ответ с серверным логом.
- Новая версия API сообщает старой вкладке о совместимости; существующая сессия не перезагружается автоматически.
